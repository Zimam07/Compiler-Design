In this lab, the intermediate code generation phase of a compiler was implemented for a selected subset of the C programming language. The previous compiler phases, such as lexical analysis, syntax analysis, symbol table construction, and semantic checking, were already available. The main purpose of this experiment was to add an Abstract Syntax Tree and use it to generate three-address code. Intermediate code is placed between the original high-level C program and the final machine code. It gives the compiler a simpler form of the program that can be analyzed, optimized, and later converted into assembly or machine instructions.

An Abstract Syntax Tree was implemented in the `ast.h` file. The AST stores the important structure of the source program without keeping unnecessary grammar details. A base class named `ASTNode` was created, and other node classes inherit from it. Expression nodes were added for variables, constants, binary operations, unary operations, assignments, array access, and function calls. Statement nodes were added for expression statements, blocks, if-else statements, while loops, for loops, return statements, and variable declarations. A program node was also created as the root of the complete AST. Each node contains the information needed to represent that part of the program and also has a `generate_code` method for producing intermediate code.

The parser was modified so that it builds the AST while parsing the input file. When the parser recognizes a variable, constant, operation, assignment, or statement, it creates the related AST node. These nodes are then connected according to the structure of the source program. For example, for the statement `a = b + c`, the parser creates a variable node for `a`, variable nodes for `b` and `c`, a binary operation node for `b + c`, and an assignment node connecting the left and right sides. In the same way, the parser creates separate AST structures for conditional statements, loops, function declarations, function calls, and return statements. This allows the complete source program to be represented in a tree form before code generation begins.

The code generation part was implemented by traversing the AST from the program node. Temporary variables such as `t0`, `t1`, and `t2` are used to store intermediate results. For example, an expression like `a = b + c * d` may be converted into instructions such as `t0 = c * d`, `t1 = b + t0`, and `a = t1`. The generator also handles unary operations, relational operations, logical operations, assignments, and array access. Constants and variables are loaded into temporary variables when necessary. The generator maintains a temporary-variable counter so that every temporary variable has a different name.

Control-flow statements are converted into labels and jump instructions. For an if-else statement, the condition is evaluated first, and the generated code uses instructions such as `if`, `goto`, and labels like `L0` and `L1` to choose between the two branches. A while loop creates a starting label, a body label, and an ending label. The condition is checked at the start of every loop iteration, and a jump returns execution to the starting label after the body is completed. A for loop generates code for its initialization, condition, body, update expression, and jump back to the beginning. This represents the high-level control structures in a form that is easier for the next compiler phase to process.

Function support was also included in the AST and code generator. Function declarations store the return type, function name, parameters, and body. Function parameters are placed into temporary variables when the function code is generated. For function calls, the arguments are evaluated and written using `param` instructions, followed by a `call` instruction. For example, a function call can produce code such as `param t0` and `t1 = call function_name, 1`. Return statements generate either `return` for a void return or `return t0` when a value is returned.

The compiler uses Flex, Yacc, and G++. Flex reads the lexical analyzer file and generates `lex.yy.c`. Yacc reads the grammar file and generates the parser files `y.tab.c` and `y.tab.h`. The generated files are compiled using G++, and the object files are linked to create the compiler executable. The compiler follows a two-pass process. In the first pass, the input C program is parsed and the AST is built. In the second pass, the AST is traversed and three-address code is generated. The output is written to `code.txt`. Information about the parsing process and AST is written to `log.txt`, while syntax and semantic errors are written to `error.txt`.

The compiler was tested using the sample input file `input3.c`. During testing, the parser successfully read the input program, the AST was generated, and the three-address code was produced. The error file showed `Total errors: 0`, which means that no syntax or semantic errors were found in the tested input. The generated code contained temporary variables, labels, arithmetic instructions, assignment instructions, and control-flow instructions. Therefore, this experiment successfully implemented AST construction and intermediate three-address code generation for the selected C language features.
